# 论文撰写

## 手稿规范

- 手稿文件（`manuscript/*.md`）**仅含正文**，不写摘要、关键词、参考文献列表
- 引用用 `[@<citeKey>]` 占位符，不展开元数据
- 撰写硬性规定见 `.litkit/<type-lang>/manuscript-spec.yaml`

## 撰写工作流

**核心原则：分工，不是取舍。** 文献提供事实，作者提供逻辑与综合。

| 层 | 内容 | 规则 |
| --- | --- | --- |
| 论证结构层 | 叙事链、逻辑连接、跨文献综合、推论、局限分析 | 由研究问题决定，以连贯、通顺、前后呼应为首要；不需要引用，也不该为引用让路 |
| 事实断言层 | 数据、他人结论、具体发现 | **必须可溯源**——硬约束，不是"兼顾" |

这个分层是整套流程的核心。**摘要全程可用**——它就是内容本身。决定"为不为引而写"的
不是摘要是否在上下文里，而是**骨架是否足够硬**：手里只有文献、没有论断链时，
模型只能拿文献当组织者。反过来，骨架够硬时摘要全程在场反而更好用（精确取数据、核对结论）。

两种反模式都禁止：

- **为引而写**：让叙事去迁就检索结果（段落靠"此外/近年来"拼接、综述式罗列、读者说不出本段要证明什么）
- **为顺而编**：给逻辑层硬塞编造的事实、数据或结论归因

### 1. 立意

探索性检索确认研究缺口真实存在、划定范围、避免选题重复
（开放式主题调研交 **deep-research** 技能——litkit 的 `search` 只做具体文献检索，不做探索式归纳）。

产出：**大纲 + 各节论断清单**。引言的"研究缺口"本身是文献论断，必须检索才能立住。

### 2. 撰写（边写边检索）

按骨架逐节写。**每遇到需要证据的位置，当场检索**（论断级英文关键词，而不是先攒一个大 query）：

| 检索结果 | 动作 |
| --- | --- |
| 有，且确实支撑该论断 | 放 `[@citeKey]` |
| 有，但只部分支撑或结论相反 | **弱化论断**；不得反过来改论断去迁就文献 |
| 没有 | 写 `[待引证]` 占位 |
| 该处是逻辑连接 / 推论 / 综合 | 直接写，不检索、不占位 |

三条纪律：

- **顺序不可反**：先有论断再检索，不是检索到什么就写什么。检索的作用是验证与支撑，不决定写什么
- `[待引证]` 只标**事实性断言**。逻辑过渡句不需要引用，标了是噪声，还会诱导给过渡句硬找文献
- 不得把需要支撑的断言改写成不承重的空话（"近年来相关研究不断深入"）来规避占位——
  这比缺引用更糟，它让论证失去承重能力

检索注意：结果自动入库，逐处检索会累积弱相关文献。用 `-n 3` 控制条数、
`--exclude` 排除跑题词，避免污染文献库影响后续选文。

### 3. 回填复核

终稿前集中处理残留 `[待引证]`：

- 再检索一轮，有支撑就补 `[@citeKey]`
- 仍无支撑 → 弱化表述，或保留占位交人工补充
- **终止条件**：同一论断连续两轮检索都无支撑 → 记录证据空白，不要无限检索

`[@citeKey]` 须置于句末标点**之前**：`结论成立[@Kxq]。`（R6.1 检查标点后紧跟引用）；
citeKey 必须来自文献库（R5.6 引用防伪会查库），严禁编造。

### 4. 验证

```bash
litkit verify manuscript/*.md --type <type> --lang <lang> --mode final
```

- `[待引证]` 必须清零（R5.2，A 类）
- 引用计数区间（spec 的 `citation.count`，R5.3）只统计 `[@citeKey]`、不统计 `[待引证]`，
  回填不彻底会提示
- **引错**（引得上但撑不住）由 `--report citation-refs` 检出：LLM 逐句评"引用句 ↔ 该文献摘要"
  的吻合度，能抓结论不符、数字编造、过度归因。配置与边界见 SKILL.md
- 引用健康检查（R5.6~R5.9）见 SKILL.md

## 验证命令

```bash
litkit verify manuscript/*.md --type <type> --lang <lang> [选项]
```

## 选项

| 选项 | 默认值 | 说明 |
|---|---|---|
| `--type` | 自动检测 | 论文类型：review / empirical |
| `--lang` | `zh` | 写作语言：zh / en |
| `--mode` | `draft` | 验证模式：chapter / draft / final（递增启用规则） |
| `--check` | 全部 | 仅运行指定检查类别（逗号分隔） |
| `--skip-check` | 无 | 跳过指定检查类别（逗号分隔） |
| `--rule` | 全部 | 仅运行指定规则 ID（逗号分隔，如 R2.1,R7.1） |
| `--skip` | 无 | 跳过指定规则 ID |
| `--report` | `json` | 报告格式：json / citation-refs（引用评分，需 LLM） |

## 检查类别

| 类别 | 说明 | 对应规则 |
|---|---|---|
| `language` | 语言合规 | R0.1, R0.2 |
| `structure` | 章节结构 | R1.1, R1.4-R1.9 |
| `heading` | 标题规范 | R1.2, R1.3, R7.1 |
| `statistics` | 统计格式 | R2.1 |
| `punctuation` | 标点符号 | R3.1, R3.2, R3.5, R3.6 |
| `style` | 行文风格 | R4.2 |
| `citation` | 引用规范 | R5.1-R5.4, R6.1 |
| `boast_words` | 自我夸大/AI痕迹 | R7.2 |
| `word_counts` | 字数统计 | R8.1-R8.3 |
| `todo` | 用户标记 | R9.1 |

## 验证模式

| 模式 | 启用规则范围 |
|---|---|
| `chapter` | 结构检查 |
| `draft` | + 数据/标点/引用 |
| `final` | + 字数/行文 |

## 退出码

- `0`：全部通过或仅 S 类需人工复核
- `1`：有 A 类违规，需修复后重跑
